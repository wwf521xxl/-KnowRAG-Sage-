# 双角色交付方案：一人导入，老板查看

> 场景：**你负责把视频/资料导进来，老板只负责看和问。**
> 这跟"老板自己导"是两套设计——他要的是**简单、可信、不用管**；你要的是**批量、可控、能兜底**。
> 核心设计只有一句话：**内容先进入待发布区，你确认后才对老板可见。**

---

## 一、角色与权限

| | 你（内容运营） | 老板（读者） |
|---|---|---|
| 账号 | 1 个管理员账号 | 1 个只读账号 |
| 能做什么 | 导入、重跑、删除、发布、看日志 | 搜索、提问、看摘要、收藏 |
| 看不到什么 | — | 后台、队列、未发布内容、报错 |
| 使用频率 | 每周 1–2 次，批量 | 每天几次，碎片时间 |

**关键差异**：老板端**没有"导入"按钮、没有设置、没有失败提示**。他打开就是"内容 + 提问框"。

---

## 二、三个状态，决定谁能看见

```
导入中（draft）  →  待发布（ready）  →  已发布（published）  →  归档（archived）
   只有你能看         只有你能看           老板可见               老板不可见
```

- **导入中**：正在转写/解析，失败也不影响老板；
- **待发布**：处理完成，但**老板还看不到**——这是质量门禁；
- **已发布**：进入老板的列表、搜索、问答范围；
- **归档**：过期/错误内容，从老板视野消失，但可恢复。

> 这一条是整个方案的核心：**老板看到的每一个字，都是你点过"发布"的。**

---

## 三、你的工作流（每周 1–2 次，每次 30 分钟）

```
1. 把新视频/资料放进投递目录（或网页批量上传）
2. 系统自动处理，你在"处理队列"看进度
3. 处理完进入"待发布"，系统给每条一个质量分
4. 你抽检几条（看摘要、点两个引用）
5. 全选 → 发布（或逐条发布）
6. 老板端出现"本周新增"，你收到一条完成记录
```

**质量门禁（自动 + 人工各一半）**

| 检查 | 自动判定 | 你要做的 |
|---|---|---|
| 转写/解析成功 | 有文本、章节 ≥ 3 | 扫一眼摘要 |
| 摘要可用 | 非空、长度合理 | 抽 1 条听/看原文 |
| 引用可跳 | 自动抽样 3 条 | 点一下确认 |
| 低置信度 | 标黄 | 决定"发布"还是"重跑" |

发布按钮两个：**"全部发布"** 和 **"只发布选中的"**。

---

## 四、老板的工作流（每天 2 分钟）

```
打开 → 看到"本周新增 5 个视频 / 12 份资料"
     → 搜索框输入问题，或点一个课程
     → 答案带时间戳/页码，点开就是原片或原文
     → 觉得有用点"收藏"，下次在"我的收藏"里
```

他不需要知道：文件在哪、用的什么模型、有没有失败、花了多少钱。

---

## 五、两个界面，一个系统

| | 老板端 `/` | 管理端 `/admin` |
|---|---|---|
| 首页 | 内容资产 + 搜索/提问 + 本周新增 | 队列、待发布、质量看板 |
| 列表 | 只显示已发布 | 全部状态，可按状态筛 |
| 详情 | 摘要、章节、原片/原文 | 同上 + 编辑标题标签 + 重跑 + 删除 |
| 问答 | 只检索已发布内容 | 可预览"发布后老板会看到什么" |
| 导航 | 无后台入口 | 有"预览老板端"按钮 |

**登录即分流**：老板账号进 `/`，你的账号进 `/admin`。同一个地址，不同角色。

---

## 六、发布后怎么通知老板

- **页面内**：首页顶部"本周新增 5 个视频"，三天内高亮；
- **企业微信/钉钉**：发布后发一条卡片"知识库更新：5 个视频、12 份资料，点击查看"；
- **每周一摘要**（可选）：上周新增内容 + 老板问得最多的 3 个问题。

不要每天推，老板会烦；**按"发布批次"推一次**就够。

---

## 七、权限与安全（老板只读）

| 项 | 设计 |
|---|---|
| 只读账号 | 老板账号无写接口权限（后端校验，不只是隐藏按钮） |
| 未发布隔离 | 列表、搜索、问答三条路径都加 `published` 过滤 |
| 删除 | 只有你能删；删除进回收站 30 天 |
| 审计 | 记录谁在何时问了什么、看了哪个文件 |
| 内网 | 只在内网/公司网络访问，不暴露公网 |

**最容易出的事故**：某个接口忘了加 `published` 过滤，老板搜到半成品。上线前专门测这一条。

---

## 八、部署（一台机器就够）

- 你的工作站或公司虚机，8C16G 起；
- 视频处理用现有 4060；也可以在你机器上处理完再同步数据库；
- 老板通过内网地址访问，手机浏览器也能开；
- 每日自动备份 `kb.db` + 文本目录。

> 两个人用，不需要集群、不需要负载均衡。**简单就是可靠。**

---

## 九、成本

| 项目 | 金额 |
|---|---|
| 服务器 | 公司虚机 0，或云 300–600 元/月 |
| 转写 | 本地 GPU 0 元 |
| 摘要 + 问答 | 每月 20–100 元（按 3000 次问答 + 新增内容） |
| 存储 | 100 小时视频约 100 GB，现成磁盘 |

## 十、改造清单（在现有系统上）

| # | 改造 | 工时 |
|---|---|---|
| 1 | `published_at` 字段 + 三状态流转 | 0.5 天 |
| 2 | 老板端过滤（列表/搜索/问答） | 0.5 天 |
| 3 | 管理端"待发布"页 + 质量分 + 批量发布 | 1.5 天 |
| 4 | 老板端精简（隐藏管理入口、首页"本周新增"） | 0.5 天 |
| 5 | 账号与角色（两个账号，后端校验） | 0.5 天 |
| 6 | 发布通知（企微/邮件） | 0.5 天 |
| 7 | 收藏 + 审计日志（可选） | 1 天 |

**合计约 5 人日**（不含 PDF/图片解析，那部分另计）。

---

## 十一、验收

- [ ] 老板账号登录后**看不到**任何"导入/设置/队列"入口
- [ ] 未发布的视频，在老板端搜索和问答里都搜不到
- [ ] 你点"发布"后，老板刷新即可看到，且收到通知
- [ ] 老板点引用，视频跳秒、PDF 跳页正常
- [ ] 老板账号调用管理接口被拒绝（不是前端隐藏）
- [ ] 你误删内容，回收站能恢复
- [ ] 处理失败的内容不会出现在老板端

---

## 十二、风险

| 风险 | 对策 |
|---|---|
| 忘了发布，老板以为没更新 | 待发布超过 3 天提醒你 |
| 发布内容有错，老板看到 | 发布前抽检 + 一键"撤回发布" |
| 老板搜到未发布内容 | 三条路径统一过滤，上线专项测试 |
| 你出差没人处理 | 队列自动跑，发布可远程；或给助理一个"仅发布"账号 |
| 内容变多找不到 | 课程/标签/时间筛选，首页有"最近更新" |

---

## 十三、一句话总结

**你是编辑，老板是读者。**
系统要保证两件事：**你导入得省事，老板看得放心。**
所以最重要的不是功能，而是那条"待发布 → 已发布"的闸门——它决定了老板对这套东西的信任。
