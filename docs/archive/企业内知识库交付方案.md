# 企业内知识库交付方案（视频 + 资料）

> 目标：把现在的单机原型，交付成老板和团队**日常能用**的内部知识库——视频、PDF、Word、图片混在一起，一个入口提问，答案能跳回原文，内容持续增长。
> 本文只讲**怎么设计和交付**：规模测算、部署形态、批量导入、权限、界面、运维、排期、成本。

---

## 一、交付目标与边界

### 1.1 谁在用

| 角色 | 人数 | 主要动作 |
|---|---|---|
| 老板 | 1 | 问问题、看摘要、看"这周新增了什么" |
| 业务/员工 | 10–50 | 找资料、看课程、问流程 |
| 管理员（你） | 1–2 | 导入内容、处理失败、看质量 |

### 1.2 什么算成功

- 老板打开就能问，答案 3–5 秒内出，**每条结论能点开原文/原片**；
- 新增 100 小时视频 + 500 份资料，**一个周末能全部入库**；
- 常见问题答对率 ≥ 85%，不知道的会明确说"没有"；
- 内容更新后，第二天就能搜到。

### 1.3 三档交付（本次做第二档）

| 档位 | 形态 | 适用 |
|---|---|---|
| A 演示版（已有） | 你的笔记本 + 本地库 | 演示、验证 |
| **B 部门版（本次）** | 公司内网服务器 + GPU 处理节点 | 老板 + 团队日常用 |
| C 全公司版 | 多节点 + SSO + 权限分级 | 后续扩展 |

## 二、容量测算（按 100 小时视频 + 500 份资料）

| 项目 | 估算 | 说明 |
|---|---|---|
| 原始视频 | ~100 GB | 1 GB/小时 |
| 原始文档 | ~5 GB | 500 份 PDF/Word/PPT |
| 转写文本 | 1200 万字 ≈ 60 MB | 1 小时 ≈ 12 万字 |
| 文档文本 | 1000 万字 ≈ 50 MB | 2 万页 |
| 检索块 | 约 3.5 万个 | 300–600 字/块 |
| 向量 | 约 150 MB | 1024 维 float32 |
| 数据库 | < 2 GB | 含索引 |
| **总存储** | **约 120 GB** | 1 TB 盘足够，留 3 年增长 |

**处理耗时（一次性）**

| 内容 | 方式 | 耗时 | 成本 |
|---|---|---|---|
| 100 小时视频 | 本地 GPU 22 倍速 | 约 5 小时 | 0 |
| 2 万页文档 | 本地解析 | 1–2 小时 | 0 |
| 2000 张图片 | 视觉模型 | 约 40 分钟 | < 2 元 |
| 全部结构化（章节+摘要） | LLM | 1–2 小时（并发） | 30–60 元 |

## 三、总体架构

| 层 | 组件 | 选型 | 说明 |
|---|---|---|---|
| 接入层 | Web / 聊天工具 | 浏览器 + Mattermost 侧栏（可选） | 内网访问，手机可开 |
| 服务层 | API + 检索 + 生成 | FastAPI + SSE | 无状态，可水平扩 |
| 处理层 | 转写 / 解析 / 结构化 | GPU worker（Python） | 批处理，与在线服务解耦 |
| 存储层 | 元数据 + 向量 + 文件 | PostgreSQL + pgvector + NAS/对象存储 | 单库搞定检索 |
| 调度层 | 队列 + 状态机 | SQLite/Redis 队列 + worker | 断点续跑、失败重试 |

**关键设计：处理与在线服务分离。**

转写是重活（吃 GPU、跑几小时），问答是轻活（几秒）。分开的好处：批量导入时不影响老板提问；GPU 机器可以只在晚上跑。

## 四、部署形态（推荐 B）

| 方案 | 硬件 | 适合 | 月成本 |
|---|---|---|---|
| A 单机一体 | 你的工作站（4060） | ≤10 人、演示 | 0 |
| **B 部门服务器 + 处理节点** | 虚机 8C32G + 1TB；处理用现有 4060 机器 | 10–50 人（推荐） | 公司虚机≈0，或云 ¥600–1200 |
| C 云上托管 | 8C32G + 200GB + GPU 按需 | 异地/多门店 | ¥1500–3000 |

**B 方案怎么搭**

```
公司内网
├─ kb-server（虚机 8C32G，常开）
│   ├─ nginx（HTTPS/内网域名）
│   ├─ kb-api（FastAPI，2 进程）
│   ├─ postgres + pgvector
│   └─ 文件目录（NAS 挂载 / 本地 1TB）
└─ kb-worker（你的 4060 机器，按需开机）
    └─ 监听队列，跑完自动退出
```

- 服务端不装 GPU，稳定、便宜；
- 处理节点只在你导入内容时开机，跑完就关；
- 以后内容多了，再给服务器加一张 4090（约 ¥1.3 万）把处理也收进去。

## 五、内容治理（"很多视频和资料"的核心）

### 5.1 目录规范

```
D:\kb-data\
├─ raw\{课程名}\{章节}\*.mp4          # 原片，只读
├─ docs\{资料类型}\*.pdf|docx|pptx     # 原始文档，只读
├─ images\{来源}\*.png                # 截图、海报
├─ media\audio\                      # 临时音频，处理完删
├─ library\{doc_id}\                 # 解析产物：transcript/outline
└─ backup\                           # 每日备份
```

### 5.2 元数据（导入时必填）

| 字段 | 例子 | 用途 |
|---|---|---|
| 课程/项目 | 五天闭门会 | 分组、筛选 |
| 讲师/作者 | 宋老师 | 筛选、引用 |
| 标签 | 私域、AI、成交 | 检索过滤 |
| 密级 | 公开 / 内部 / 机密 | 权限过滤 |
| 日期 | 2026-02 | 排序、"本周新增" |

### 5.3 去重与生命周期

- **去重**：文件 sha256，同一文件改名/换目录不重复处理；
- **原片**：永久保留（可迁 NAS），不对外提供下载；
- **音频**：转写完成即删（100 小时约 1.4 GB，无所谓但没必要留）；
- **文本**：永久；**向量**：可重建（换模型时重算）。

### 5.4 备份

- 每日增量：`kb.db` → 备份目录（保留 30 天）；
- 每周全量：数据库 + `library/` 文本 + 配置；
- 每季度做一次恢复演练（真的恢复一次，别只备份）。

## 六、批量导入流水线

```
投递（复制到 raw/ 或上传页）
   ↓
扫描（sha256 去重、读元数据、识别格式）
   ↓
队列（状态机：pending → parsing → structured → ready）
   ↓
解析（视频 ASR / PDF 抽文 / 图片视觉）
   ↓
结构化（摘要、章节、标签）
   ↓
切块 + 向量化 + 入库
   ↓
抽检（随机 5%，错误率 > 5% 报警）
```

**四条硬要求**

1. **断点续跑**：任何一步失败，重跑从断点继续，不重转；
2. **失败隔离**：一条坏了不影响队列，失败单独列出可重试；
3. **限速**：LLM 并发 4、视觉模型并发 4、转写串行；
4. **可见进度**：页面显示 `x/N`、当前文件、预计剩余时间。

## 七、检索与问答（企业级）

### 7.1 检索

- **混合召回**：向量（语义）+ BM25（关键词）+ 元数据过滤；
- **重排**：rerank 取前 6 块；
- **权限过滤**：按密级和部门过滤（SQL 层做，不在 Prompt 里做）；
- **阈值拒答**：相关度不够直接说"没有"，不硬编。

### 7.2 回答

- 结论 → 要点 → 引用；
- 每个引用带类型：`▸ 12:34`（视频）/ `▸ 第12页`（PDF）/ `▸ 图3-2`；
- 多视频对比时，按来源分组；
- 不确定的内容标注"推断"。

### 7.3 体验细节

- 首字 ≤ 5 秒（流式）；
- 支持追问（保留上下文 3 轮）；
- "这个问题没人问过"时，给 3 个相关推荐；
- 问题日志进入后台，每周看 Top 20 未命中问题，补内容。

## 八、界面设计（老板看到的样子）

### 8.1 首页：内容资产

- 顶部一行数字：`128 个视频 · 960 份资料 · 本周新增 5 个视频 / 12 份资料`；
- 中间：搜索框（也当提问框）+ 3–5 个常见问题快捷入口；
- 底部三块：最近更新、热门课程、我的收藏。

### 8.2 列表与详情

- 筛选：类型（视频/文档/图片）、课程、讲师、标签、时间；
- 详情：摘要、章节目录、原文/原片、相关推荐；
- 视频带播放器，PDF 带阅读器，图片带大图。

### 8.3 问答

- 对话式，答案带引用；
- 引用点开：视频跳秒、PDF 跳页、图片看原图；
- 每条答案可"有用/没用"，进入质量看板；
- 支持"只看视频/只看文档"。

## 九、账号与权限

| 角色 | 权限 |
|---|---|
| 老板 | 全部内容只读 + 提问 + 看统计 |
| 员工 | 按部门/标签可见 + 提问 |
| 管理员 | 导入、删除、重跑、看日志 |
| 访客 | 仅公开内容（可选） |

- 第一版：简单账号（用户名+密码），10 个账号足够；
- 第二版：接企业微信/钉钉扫码或 SSO；
- **审计**：谁在什么时候问了什么、看了哪个文件，留日志 90 天。

## 十、运维与保障

| 项 | 做法 |
|---|---|
| 可用性 | 工作日 8:00–22:00 可用；服务异常自动重启 |
| 监控 | 接口延迟、错误率、队列积压、磁盘、API 余额 |
| 告警 | 错误率 >5%、队列积压 >50、磁盘 >80% → 微信/邮件 |
| 备份 | 每日增量 + 每周全量，保留 30 天 |
| 更新 | 提示词/模型灰度：先 10% 流量，对比 20 题再全量 |
| 内容更新 | 每日 2:00 扫描投递目录，自动入队 |

## 十一、成本（按 100 小时视频 + 500 份资料）

### 一次性

| 项目 | 金额 |
|---|---|
| 开发与迁移（约 20–25 人日） | 自建：时间成本；外包约 3–4 万 |
| GPU（可选，后期） | 0（先用现有 4060）/ 1.3 万（4090） |
| 存储 | 已有 NAS/磁盘，0 |

### 每月

| 项目 | 金额 |
|---|---|
| 服务器（公司虚机） | 0–300 元 |
| 云服务器（若外购） | 600–1200 元 |
| LLM + 视觉（问答 3000 次 + 新增内容） | 50–200 元 |
| 备份存储 | 10–30 元 |
| **合计** | **约 100–500 元/月** |

> 强调：**主要成本是人力和服务器，不是 API**。100 小时视频全部转写+结构化，一次性也就 60 元左右。

## 十三、风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 转写质量不达标（口音/术语） | 搜索不到、答错 | 术语表 + 抽检；关键课程用大模型重转 |
| 扫描版 PDF 无文字 | 解析为空 | 标记 `needs_ocr`，二期 OCR |
| 内容涉密 | 合规风险 | 内网部署、密级过滤、不出公网 |
| 你的电脑成为单点 | 处理停摆 | 处理节点可换机；队列断点续跑 |
| 老板问的问题超纲 | 体验差 | 拒答 + 推荐相近内容 + 记录补内容 |
| 内容增长失控 | 磁盘/成本 | 容量看板、生命周期、季度清理 |
| 版权/分发 | 法律风险 | 仅内部检索，不提供原片下载 |
| 交付后没人维护 | 逐渐荒废 | 明确责任人 + 每周 30 分钟巡检 |

## 十四、交付物清单

**给老板**
1. 一个内网地址 + 账号；
2. 一页使用说明（怎么问、能问什么、不能问什么）；
3. 内容资产看板（有多少视频/资料、本周新增）。

**给 IT/运维**
4. 部署文档（Docker Compose、目录、端口、备份脚本）；
5. 监控与告警配置；
6. 恢复演练记录。

**给你自己**
7. 导入手册（目录规范、元数据模板、失败处理）；
8. 质量看板（未命中问题、抽检结果、成本）。

## 十五、给老板的一页说明（可直接打印）

> **这是什么**
> 把公司的课程、会议、资料变成"能搜、能问"的知识库。不用看完 2 小时视频，也能知道它讲了什么、第几分钟讲了什么。
>
> **怎么用**
> 打开内网地址 → 直接问，比如"新人培训里报销流程分几步"；答案后面有时间/页码，点一下跳到原片或原文。
>
> **它擅长**
> 找事实、找原话、跨视频/跨资料对比、定位到具体时间或页码。
>
> **它不擅长**
> 画面里的图表细节、没说出口的暗示、资料里根本没有的内容（会明确说"没有"）。
>
> **怎么更新**
> 新视频/新资料放进共享目录，第二天自动可搜；急用找管理员手动导入。

## 十六、建议的下一步

1. **先定部署形态**：公司有没有可用虚机？没有就走"你的机器 + 内网 IP"过渡；
2. **先迁 5 个视频**，验证迁移不回归；
3. **再批量导入 20 个视频 + 50 份 PDF**，跑 50 题评测；
4. **老板试用两周**，根据未命中问题补内容；
5. 稳定后再谈全公司、SSO、Mattermost 集成。

> 一句话：**先让老板一个人用顺，再谈全公司。**
